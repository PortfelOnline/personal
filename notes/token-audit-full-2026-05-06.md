## 2. Где уходит 40% токенов DeepSeek (waste)

### Проблема: DeepSeek через прокси НЕ КЭШИРУЕТ контекст

**Claude Code (native):** 
- Кэширует 90% контекста между запросами
- За 1 сессию из 648K токенов → только ~65K реально отправляется
- Пример: Sonnet прочитал 4,434M из кэша, отправил только 124M нового

**DeepSeek (через ds-proxy):**
- Каждый запрос шлёт ПОЛНЫЙ контекст заново
- Flash: 1,022M input + 229M cache_read = 1,251M отправлено
- Если бы DS имел кэш Клода: отправилось бы ~125M вместо 1,251M
- **Waste: ~1,126M токенов (90% — ПОВТОРНАЯ ОТПРАВКА ОДНОГО И ТОГО ЖЕ)**

### Конкретные места потерь

1. **System prompt + CLAUDE.md + settings (~50K)**: каждый запрос шлёт заново на DeepSeek
   - Claude кэширует это один раз (30 токенов вместо 50,000 — экономия 99.94%)

2. **Read tool outputs (большие файлы)**: результаты Read возвращаются в контекст
   - Claude: cache hit → $0.30/M
   - DeepSeek: каждый раз полная стоимость $0.14/M
   - Но Claude дешевле за счёт cache hit!

3. **Tool call history**: вся история вызовов инструментов повторяется
   - 20 тулов × 30K контекста = 600K — Клод кэширует, DS шлёт заново
