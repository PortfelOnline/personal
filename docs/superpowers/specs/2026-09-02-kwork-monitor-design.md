# kwork-monitor — дизайн

Статус: дизайн пересмотрен и самопроверен 7 сентября 2026; ожидает подтверждения пользователя перед планом реализации.

## Задача

Агент отслеживает новые проекты Kwork из официальных email-уведомлений Биржи (ниша: IT/разработка, боты, автоматизация, AI-агенты, парсинг, интеграции), уведомляет о них в отдельный Telegram-бот вместе с готовым черновиком отклика (сгенерированным через мост Code Assist), пользователь сам решает — редактировать и отправлять отклик на Kwork вручную. Полного авто-отправления нет (отклик на Kwork платный и необратим).

Аналогия по духу — уже существующий на `n` кейс мониторинга Telegram-чатов на релевантные запросы (вероятно, один из вертикалей GMA/get-my-agent.com, например йога-студия), но здесь источник — kwork, а не Telegram-чаты.

## Решённые вопросы (из брейнсторминга)

- **Источник данных Kwork**: только официальные email-уведомления Биржи. В аккаунте Kwork пользователь включает уведомления и выбирает нужные рубрики. Kwork сам описывает этот способ: уведомления о новых проектах по выбранным рубрикам приходят на email ([инструкция Kwork](https://blog.kwork.ru/insajdy/10-sovetov-frilanseru-kak-uvelichit-svoyu-produktivnost)).
- **Ограничение источника**: скрипт не открывает Kwork, не использует cookie и не скрапит HTML. Это обязательно: правила Kwork запрещают роботов и автоматические средства для отслеживания, извлечения или сбора данных из Сервиса ([пользовательское соглашение](https://kwork.ru/terms_of_service)).
- **Отправка отклика**: НЕ автоматом. Только уведомление + черновик, пользователь отправляет отклик на kwork сам.
- **Ниша фильтрации**: IT/разработка, боты, автоматизация, AI-агенты, парсинг, интеграции.
- **Частота проверки**: раз в 1 час (cron).
- **Контекст для генерации откликов**: да, нужен бриф о пользователе/услугах — Claude сгенерировал черновик (см. ниже), пользователь его доработает.

## Архитектура

Один Python-скрипт `kwork_watcher.py` на сервере `n` (167.86.116.15), запускается по cron раз в час. Без новых демонов/сервисов — паттерн как у существующих одноразовых cron-скриптов (`parse_watchdog.sh`, `geo_warm.py`). Скрипт обращается только к выделенному почтовому ящику по IMAP и к Telegram/мосту генерации; запросов к Kwork нет.

### Компоненты

1. **Mail reader** — читает непрочитанные/новые письма выделенного ящика по IMAP. Принимаются только письма с разрешённого отправителя и/или шаблона темы Kwork, заданных в `config.yaml`.
2. **Email parser** — извлекает из уведомления тему проекта, ссылку, бюджет и доступный фрагмент ТЗ. Письма, которые не соответствуют ожидаемому шаблону, не отправляются в генератор и попадают в SQLite-очередь ошибок; алерт по одному `Message-ID` отправляется не более одного раза.
3. **Dedup store** — SQLite `seen_orders.db` (`Message-ID`, ссылка/идентификатор проекта, ts) — уведомление обрабатывается один раз, даже если письмо прочитано повторно.
4. **Relevance filter** — по ключевым словам и рубрикам отсеивает нерелевантные письма до генерации.
5. **Proposal generator** — вызывает мост Code Assist (`codeassist-openai-shim.py`, OpenAI-совместимый эндпоинт) с system-промптом = бриф пользователя + текст из email → черновик отклика на русском. Если в уведомлении недостаточно ТЗ, явно помечает это в черновике.
6. **Notifier** — отдельный Telegram-бот (токен даёт пользователь), шлёт: заголовок проекта, ссылку, бюджет, извлечённый фрагмент ТЗ и черновик отклика.
7. **Config** — `PROFILE.md` (бриф, см. ниже) + `config.yaml` (IMAP-папка, разрешённые отправители/темы, ключевые слова, интервал, Telegram chat id). Секреты хранятся отдельно от Git с правами только владельца.

### Data flow

Kwork → официальное email-уведомление → cron читает IMAP → parse → filter → diff vs SQLite → для новых: generate proposal via bridge → send to Telegram → mark as seen in SQLite. При ошибке генерации уведомление со ссылкой всё равно уходит; при ошибке Telegram запись не помечается обработанной и повторяется на следующем тике.

### Обработка ошибок

- **Нет новых писем Kwork** → штатное состояние, без алерта.
- **IMAP недоступен/учётные данные невалидны** → Telegram-алерт с краткой причиной, скрипт завершается; следующий cron повторит попытку.
- **Изменился шаблон email Kwork** → в Telegram уходит один алерт «не удалось разобрать уведомление Kwork» с `Message-ID`; письмо остаётся в очереди ошибок для ручной проверки, без генерации.
- **Мост Code Assist недоступен** → в Telegram уходит голая ссылка на заказ без черновика + пометка «черновик не сгенерирован», остальные заказы не блокируются.
- **Telegram недоступен** → лог ошибки, запись не помечается обработанной; retry на следующем тике, пока доставка не подтвердится.

### Тестирование

Ручной прогон `kwork_watcher.py --dry-run` — читает тестовые `.eml`-фикстуры или выбранные письма в read-only режиме, логирует результат в консоль, не пишет в SQLite и не шлёт в Telegram. Набор тестов покрывает: валидное уведомление, нерелевантный проект, письмо с изменённой структурой, недоступную генерацию и повтор того же `Message-ID`.

## Открытые вопросы при возобновлении

- Пользователь может захотеть скорректировать бриф (цены/сроки точно нужно заполнить).
- Нужно решить, где именно на сервере `n` будет жить директория проекта (по аналогии с другими: `/root/kwork-monitor/`?).
- Нужен новый Telegram-бот-токен от пользователя (он сказал, что создаст бота сам).
- Нужен выделенный почтовый ящик или доступ к существующему ящику через отдельный IMAP app password; секрет не хранится в репозитории.
- В Kwork нужно вручную включить email-уведомления Биржи и выбрать рубрики. Точность черновика зависит от полноты текста, который Kwork присылает в письме.

## Самопроверка спецификации

- Убрана не соответствующая правилам Kwork схема с cookie и скрапингом. Скрипт не обращается к сайту Kwork и не автоматизирует действия в нём.
- Ясно определён авторитетный вход: email-уведомление, а не HTML страницы. Это исключает неоднозначность о частоте запросов, сессии и антибот-защите.
- Дедупликация и повторная доставка теперь устроены безопасно: запись считается обработанной только после успешной доставки в Telegram; ошибка генерации не скрывает новый проект.
- Конфиденциальные данные вынесены из репозитория; в LLM передаётся лишь текст уведомления и профиль пользователя. Автоматической отправки платных откликов нет.
- MVP сознательно не обещает полный текст ТЗ, если его нет в email: Telegram всегда содержит ссылку, а пользователь открывает проект и отправляет финальный отклик вручную.
